# TSS Network Threat Model — Phase 2.5

| ID | Attacker Capability | Attack | Impact | Mitigation | Remaining Assumption |
|----|---------------------|--------|--------|------------|----------------------|
| network attacker | Dolev-Yao: intercept, delay, drop, replay, modify | replay old session message to new session | forge or confusion | `TssEnvelope` session_id/wallet/chain/digest/protocol_version binding + `derive_session_id` + `validate_against` | session randomness fresh, no share leakage |
| malicious participant | controls one share, sends invalid messages | wrong round, wrong digest, duplicate, malformed | abort or identifiable abort, no valid sig | synedrion `InteractiveSigningError` per round, transport `check_no_duplicate`/`check_round_order`, handshake validates | at least t honest participants for liveness |
| compromised participant | extracts share + network key | use share to sign alone | single share cannot sign (threshold), network key compromise ≠ share compromise (separate NetworkKeypair vs ThresholdKeyShare) | participant identity (`NetworkKeypair`) separate from `ThresholdKeyShare`; threshold 2-of-3 | <t compromised, storage encrypted |
| malicious coordinator | relays, can drop/delay/modify | digest substitution, participant impersonation, bypass threshold | sign wrong digest, forge | envelope `digest` binding + `verify` with `ParticipantIdentity`, handshake validates wallet/chain/nonce/policyVersion, provider checks `threshold` and `group_address` | coordinator is untrusted for safety, not for liveness |
| stale participant | old share after rotation | mix old B share with new D | invalid session (stale participantSetVersion) | `participant_set_version` in `KeyLifecycle::key_id`, `is_stale` check, session binds to version | governance must increment version |
| compromised storage | read share file | decrypt share | share leakage | `EncryptedShareStore` ChaCha20Poly1305 at rest, 0o600 permissions, zeroize on delete, passphrase via env/keychain (not committed) | passphrase not co-located |
| participant replacement attack | arbitrary set change | add attacker D without governance | change group key silently | `RecoveryManager` governs set changes; TSS `KeyResharing` only with authorized `NewHolder`; `verify_wallet_identity` fails if group key mismatched | governance threshold holds |
| session replay | capture old envelope | replay to new session/digest/wallet | forge | `TssEnvelope.validate_against` + `SessionBinding` immutability + terminal state `ABORTED/FAILED` never resurrects | session_id includes random |
| message substitution | modify payload in transit | change TSS message | invalid proof → abort | `TssEnvelope.signature` over `to_sign_bytes()` verified against `ParticipantIdentity` | network key not compromised |
| connection hijacking | MITM without key | impersonate A as B | sign as B | `authenticate` via `NetworkKeypair` + `ParticipantIdentity::verify`, mTLS placeholder for TCP | cert pinning in production |
| configuration mismatch | wrong chain/wallet/threshold | sign on wrong chain | loss or wrong execution | `ThresholdEcdsaProvider::new` chain check, `sign` chain vs provider chain, `ThresholdParticipantSet::verify_wallet_identity`, `KEYMESH_SIGNING_MODE` explicit, mainnet blocked | env must be correct |
